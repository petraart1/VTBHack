# Решение проблем с авторизацией и подключением к API

## Проблема: Авторизация работает без проверки

### Причина
В `LoginScreen.kt` была заглушка, которая просто вызывала `onLoginSuccess()` без реальной проверки.

### Решение
1. ✅ Создан `LoginViewModel` с реальной проверкой через API
2. ✅ Добавлена интеграция с `AuthApiService`
3. ✅ Добавлено логирование для отладки

### Что изменилось
- Теперь при попытке входа отправляется запрос на `http://158.160.102.225/api/v1/auth/login`
- Если endpoint не существует (404), будет показано соответствующее сообщение
- Все действия логируются в Logcat с префиксами `[LoginViewModel]`

## Проблема: Нет логов в Logcat

### Причина
1. Фильтр слишком строгий (например, только `AccountRepository`)
2. Timber не инициализирован правильно
3. Логи не генерируются, потому что код не выполняется

### Решение

#### Шаг 1: Проверьте фильтр в Logcat
1. Откройте Logcat в Android Studio
2. **Очистите фильтр** или используйте более широкий фильтр
3. Попробуйте фильтры:
   - `LoginViewModel` - для логов авторизации
   - `AccountRepository` - для логов счетов
   - `TransactionRepository` - для логов транзакций
   - `AuthRepository` - для логов авторизации
   - `OkHttp` - для HTTP запросов
   - Или просто **без фильтра** для всех логов

#### Шаг 2: Проверьте, что Timber инициализирован
В `RadarApplication.kt` должна быть инициализация Timber. Проверьте логи при старте приложения - должно быть:
```
🚀 [RadarApplication] Приложение запущено в DEBUG режиме
📱 [RadarApplication] Логирование Timber включено
```

#### Шаг 3: Проверьте уровень логирования
В Logcat выберите уровень логирования:
- **Verbose** - все логи
- **Debug** - отладочные логи (рекомендуется)
- **Info** - информационные логи
- **Warn** - предупреждения
- **Error** - только ошибки

## Проблема: Авторизация не работает (показывает ошибку)

### Вариант 1: Endpoint не существует (404)
**Симптомы:**
- В логах видно: `❌ [LoginViewModel] Код ответа: 404`
- Сообщение: "Endpoint авторизации не найден"

**Решение:**
1. Проверьте Swagger документацию: http://158.160.102.225:8080/swagger-ui/index.html
2. Если endpoint `/api/v1/auth/login` не существует, нужно:
   - Добавить его на Backend
   - Или использовать OAuth2 для авторизации через банк

### Вариант 2: Сервер недоступен
**Симптомы:**
- В логах видно: `Failed to connect` или `Unable to resolve host`
- Сообщение: "Не удалось подключиться к серверу"

**Решение:**
1. Проверьте интернет-соединение
2. Проверьте доступность сервера:
   ```bash
   ping 158.160.102.225
   ```
3. Проверьте, что сервер запущен и доступен

### Вариант 3: Неверные credentials (401)
**Симптомы:**
- В логах видно: `❌ [LoginViewModel] Код ответа: 401`
- Сообщение: "Неверный email или пароль"

**Решение:**
1. Используйте правильные credentials
2. Проверьте формат email и пароля
3. Убедитесь, что аккаунт существует в системе

## Проблема: Backend не связан с Frontend

### Признаки
1. ✅ Авторизация работает без проверки (исправлено)
2. ✅ Данные всегда одинаковые (проверьте логи)
3. ✅ Нет HTTP запросов в Logcat (проверьте фильтр `OkHttp`)

### Как проверить связь

#### Способ 1: Проверьте HTTP запросы
1. Откройте Logcat
2. Установите фильтр: `OkHttp`
3. Попробуйте авторизоваться
4. Должны увидеть:
   ```
   D/OkHttp: --> POST http://158.160.102.225/api/v1/auth/login
   D/OkHttp: Content-Type: application/json
   D/OkHttp: {"email":"...","password":"..."}
   D/OkHttp: <-- 200 OK (или другой код)
   ```

#### Способ 2: Проверьте логи репозиториев
1. Откройте Logcat
2. Установите фильтр: `LoginViewModel` или `AccountRepository`
3. Выполните действия в приложении
4. Должны увидеть логи с префиксами:
   - `🌐 [LoginViewModel] Используется РЕАЛЬНЫЙ API: ...`
   - `📡 [LoginViewModel] Ответ получен. Код статуса: ...`

#### Способ 3: Проверьте сетевой трафик
Используйте Charles Proxy или Fiddler для перехвата HTTP запросов.

## Что делать дальше

### Если endpoint `/api/v1/auth/login` не существует:
1. **Используйте OAuth2** для авторизации через банк

2. Проверьте, что все поля отправляются правильно
3. Проверьте логи Backend для понимания проблемы

### Для проверки работы API:
1. Откройте Swagger: http://158.160.102.225:8080/swagger-ui/index.html
2. Попробуйте выполнить запрос вручную
3. Сравните с запросами из приложения
