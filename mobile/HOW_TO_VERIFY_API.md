# Как проверить, что приложение работает с реальными API

Этот документ описывает несколько способов проверки того, что приложение использует реальные данные из API, а не мок-данные.

## Способ 1: Проверка логов в Android Studio (Logcat)

### Шаг 1: Откройте Logcat
1. В Android Studio откройте вкладку **Logcat** (внизу экрана)
2. Выберите ваше устройство/эмулятор в списке устройств
3. Установите фильтр на тег `AccountRepository`, `TransactionRepository` или `AuthRepository`

### Шаг 2: Выполните действия в приложении
- Попробуйте авторизоваться
- Загрузите счета
- Загрузите транзакции

### Шаг 3: Проверьте логи

Вы должны увидеть логи с такими префиксами:
- ✅ `🌐 [AccountRepository] Используется РЕАЛЬНЫЙ API: http://158.160.102.225/api/v1/bank/accounts`
- ✅ `📡 [AccountRepository] URL запроса: http://158.160.102.225/api/v1/bank/accounts`
- ✅ `✅ [AccountRepository] Успешно получено X счетов из РЕАЛЬНОГО API`

**Если вы видите эти логи** - приложение работает с реальными API! ✅

**Если вы НЕ видите эти логи** - возможно, используются мок-данные или есть проблемы с подключением.

## Способ 2: Проверка HTTP запросов через HttpLoggingInterceptor

### Шаг 1: Откройте Logcat
1. В Android Studio откройте вкладку **Logcat**
2. Установите фильтр на тег `OkHttp` или `okhttp3`

### Шаг 2: Проверьте логи запросов

Вы должны увидеть подробные HTTP запросы:

```
D/OkHttp: --> GET http://158.160.102.225/api/v1/bank/accounts
D/OkHttp: Authorization: Bearer <ваш_токен>
D/OkHttp: <-- 200 OK http://158.160.102.225/api/v1/bank/accounts (1234ms)
D/OkHttp: {"accounts":[...]}
```

**Ключевые признаки реального API:**
- ✅ URL начинается с `http://158.160.102.225/api/v1/`
- ✅ Есть заголовок `Authorization: Bearer ...`
- ✅ Код ответа 200 (или другой успешный код)
- ✅ В ответе есть реальные данные в формате JSON

## Способ 3: Проверка через сетевой трафик

### Использование Charles Proxy или Fiddler
1. Установите Charles Proxy или Fiddler на ваш компьютер
2. Настройте Android устройство/эмулятор для использования прокси
3. Выполните действия в приложении
4. Проверьте перехваченные запросы

**Вы должны увидеть запросы к:**
- `http://158.160.102.225/api/v1/auth/*` - для авторизации
- `http://158.160.102.225/api/v1/bank/*` - для банковских данных
- `http://158.160.102.225/api/v1/radar/*` - для радара

## Способ 4: Проверка через сравнение данных

### Сравните данные из приложения с данными из Swagger
1. Откройте Swagger UI: http://158.160.102.225:8081/swagger-ui/index.html
2. Авторизуйтесь через Swagger
3. Выполните тот же запрос, что и в приложении
4. Сравните результаты

**Если данные совпадают** - приложение работает с реальными API! ✅

## Способ 5: Проверка через ошибки API

Если API возвращает ошибку (например, 401 Unauthorized), это также подтверждает, что приложение пытается подключиться к реальному API, а не использует моки.

### Типичные ошибки:
- **401 Unauthorized** - токен отсутствует или неверный
- **404 Not Found** - неправильный endpoint
- **500 Internal Server Error** - проблема на стороне сервера

Все эти ошибки означают, что приложение **подключается к реальному API**.

## Что делать, если приложение НЕ работает с реальными API?

### Проблема 1: Не видно логов с префиксом "🌐"
**Решение:** Проверьте, что репозитории не используют `MockDataService`. В коде должны быть вызовы `bankApiService`, а не `mockDataService`.

### Проблема 2: Запросы идут на другой URL
**Решение:** Проверьте файл `NetworkModule.kt` - базовые URL должны быть:
- `http://158.160.102.225/api/v1/auth/`
- `http://158.160.102.225/api/v1/bank/`
- `http://158.160.102.225/api/v1/radar/`

### Проблема 3: Ошибка подключения
**Решение:** 
- Проверьте интернет-соединение
- Убедитесь, что сервер доступен: `ping 158.160.102.225`
- Проверьте, что в `AndroidManifest.xml` есть разрешение `INTERNET`

## Быстрая проверка через код

Откройте файл и найдите эти строки:

1. **AccountRepositoryImpl.kt** - строка должна содержать:
   ```kotlin
   val response = bankApiService.getAccounts("Bearer $accessToken")
   ```
   НЕ должно быть:
   ```kotlin
   val mockAccounts = mockDataService.getMockAccounts()
   ```

2. **TransactionRepositoryImpl.kt** - аналогично должно быть:
   ```kotlin
   val response = bankApiService.getTransactions(...)
   ```

3. **AuthRepositoryImpl.kt** - должно быть:
   ```kotlin
   val response = authApiService.exchangeCodeForToken(...)
   ```

## Итоговая проверка

✅ **Приложение работает с реальными API, если:**
1. В логах видно URL `http://158.160.102.225/api/v1/*`
2. HTTP запросы отправляются на правильный сервер
3. Получены реальные данные (или реальные ошибки от сервера)
4. Данные совпадают с данными из Swagger UI

❌ **Приложение НЕ работает с реальными API, если:**
1. В логах нет запросов к `158.160.102.225`
2. Данные всегда одинаковые (типично для моков)
3. Нет ошибок подключения, даже при отсутствии интернета
4. В коде используются вызовы `mockDataService`
